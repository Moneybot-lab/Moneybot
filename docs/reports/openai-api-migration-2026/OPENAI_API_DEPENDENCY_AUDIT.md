## Configuration and production evidence

1. `app.py:4` creates Flask. `moneybot/app_factory.py:482–491,602–609` reads process environment once per app and injects one advisor. Default feature flag is false; only case-insensitive `true` enables it (no trim). A nonblank `AI_API_KEY` is also required. `AI_PROVIDER` defaults to `openai`; provider is normalized and any other value skips calls. `OPENAI_API_KEY` and illustrative `OPENAI_MODEL_*` names do not configure this code.
2. An explicit `AI_MODEL` wins over the factory default. An empty value falls back again to `gpt-5-mini` in `ai_advisor.py:111,119`; a whitespace-only model becomes an empty ID after trimming. No alias resolution, lifecycle validation, alternate model, database or per-user model selection. Factory timeout 6 s per attempt overrides direct construction's 2.5 s. Default shared cooldown 120 s; Quick Ask local TTL 300 s. A future default change alone cannot fix an overriding retired ID.
3. `render.yaml:2,8,66` declares Key Value, web and a market-stream worker. It declares no AI selection keys or cron service. Live dashboard settings, linked groups and externally scheduled HTTP clients can differ. Render service-specific variables override group values; collisions across groups have no guaranteed precedence. Saved-only changes take effect at a subsequent deploy. Ignore credentials and unrelated values in verification. [Render configuration](https://render.com/docs/configure-environment-variables)
4. No AI selection or provider credential reference found in tracked Actions jobs. A read of repository Actions secret **name metadata only** returned HTTP 403. Physical presence of unused org, repo, environment or dashboard keys remains unknown. Bundled SQLite has only users, watchlist items and sold trades; ORM/migrations and constructor expose no model-settings lookup. No production database connection or query.
5. The earlier November 3 trace recorded 28 lots, 56 attempts, 28 usable enhancements, approximately 147 s of OpenAI time and 153.5 s total on the older request profiles. It identifies 6 s timeout/120 s cooldown on that worker. It lacks model ID, token counts and spend. An earlier report's unknown enablement was superseded for that one trace only. The current code changed its first portfolio profile. [Trace](../portfolio_ai_latency_repair.md#production-evidence-and-root-cause) · [Earlier report](../portfolio_latency_after_pr667.md)

## Reliability and API compatibility

| Condition | Current result | Required control or test |
|---|---|---|
| Retired/inaccessible model, bad auth, unsupported parameter | Both paths turn non-5xx HTTP errors into rule fallback and a shared process cooldown. A single misconfiguration can suppress the other workload. Status alone does not distinguish access denial from retirement. | Validate IDs, effort and deadline offline; record status and allowlisted error code. Do not retry credential, permission, invalid-body, missing-model or billing failures. Alert for operator action. |
| Rate limit / capacity / service outage | 429 usually enters the same generic cooldown; no Retry-After. 5xx and timeout can retry immediately once. Portfolio cools down after exhaustion. Quick helper normally returns None on exhausted timeouts/5xx, bypassing the outer cooldown. Other transport exceptions fall into broad handlers. | Bound attempts to two total within one deadline. Honor Retry-After for transient limits/overload if it fits, otherwise degrade. Use capped exponential backoff with jitter, separate fault classes and per-workload breaker probes. |
| Malformed, incomplete, refusal, truncation | Portfolio validates the enum, nonempty reason and two nonblank strings per list; incomplete status is rejected, absent status accepted. Retries malformed once, then applies portfolio-only pause. Quick accepts any JSON object before a loose narrative check; a status-incomplete envelope, invalid fields or truncated guidance may appear enhanced. | Validate the exact schema locally, stop on refusal, check status, type and output budget before publication; differentiate refusal, invalid, exhausted and missing authority. Bound schema repair separately from transient retry. |
| Exhausted reasoning/output budget | Same 420/minimal portfolio payload sent twice; Quick uses 220/low then 420/minimal. Reasoning uses output allowance. Only Portfolio reports bounded usage/incomplete counters. | Test both attempts under the selected model. Minimize total attempts and price complete output. Scope retry budgets and approved cap per view/user. |
| Missing market or model decision | Quick's rule selector can return HOLD OFF with missing inputs. Portfolio can substitute entry for current price, produce a default HOLD or an actionable rule fallback. Raw nested text may imply an unavailable decision. Authenticated modal already has neutral guidance. | Preserve existing authoritative decisions and provenance. Explicitly display unavailable for missing authority; do not pass substitute prices as observations or invent probability/confidence. This is a separately reviewed behavior change in unlocked/missing-data cases. |

Both requests are synchronous, single-turn, bare string `input`, `text.format.type=json_schema`, `strict=true`, and `max_output_tokens`. No temperature, top_p, logprobs, tools, system/developer message array, session state, previous response ID, SDK automatic retries or background execution. Keep Responses. Quick retry and **both** Portfolio attempts send unsupported `minimal` on the proposed 6-family candidates. A single environment substitution can break all portfolio attempts without an obvious HTTP error at the MoneyBot endpoint. Preserve nested output parsing and local NDJSON semantics.
