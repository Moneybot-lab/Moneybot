# Validation plan for a separately approved migration

No application test, live inference, market-provider request, AWS call or scoring run was executed during this audit. The following acceptance criteria are proposed for the migration. Protected MoneyBot and Alpha Atlas pass/fail criteria retain their existing definitions.

## Reproduction protocol

Pin audited base SHA, candidate commit, capability-registry version, exact model ID, reasoning setting, timeout, budgets and schema version. Use a temporary workspace, temporary SQLite/runtime directories, fixed clock, synthetic symbols and synthetic account/lot IDs. Disable external DNS/socket egress in the test process, intercept both transport call sites and forbid unmatched HTTP, cloud, scheduler and provider clients. Do not import production credentials or reuse the tracked SQLite file as test storage. Baseline and candidate receive the same inputs. Save only fixture IDs, expected and observed fields, aggregate metrics, hashes and pass/fail. Never persist real prompts, holdings, identities or provider responses.

Construct a versioned fixture set of at least 24 cases covering positive/negative/neutral news, ambiguous or missing data, asynchronous stale quote, conflicting signals, positive/negative P&L, zero/unknown entry, split basis, two same-symbol lots with different cost bases, concentration, changed profile, threshold-adjacent recommendations, deterministic lock present/absent, evidence gates closed and an explicit no-decision case. Include risk, EPS versus revenue direction, units/currency, basis points versus percent and rounding. Use hand-computed ground truth for calculations. Existing notification and scanner ranking outputs stay the baseline; no new LLM classifier is needed.

Cover missing/blank/whitespace ID, explicit overrides, disabled/missing key, incompatible effort, unsupported/deprecated ID, primary and retry. Disable dispatch, email, push, job scheduling and provider transports. | Existing deterministic scores, order, notification eligibility, holdings/ledger, response schemas and chronology match baseline, except an explicitly approved unavailable representation. Zero unexpected AI calls on deterministic routes. |
| T08 Alpha Atlas and research separation | Compare git blobs for all protected files. Use existing authorized read-only evidence or a frozen **synthetic** forecast object in mocks, including null. Replay only synthetic route-level messages. | T09 Spend, load and safeguards | Fixed clock and mock transports for 1/5/20/28 lots, Clearview 1/5/20 symbols, repeated symbols in different lots, simultaneous views, both attempts, exhaustion and cache miss/hit. Repeat synthetic workloads 20 times at identical concurrency on both versions. Verify model and token provenance, including cached and reasoning tokens. | Zero cross-user disclosure, no unbounded queue/calls, no paid work after cancellation or quota gate beyond an already in-flight attempt. Report p50/p95 to first paint and valid advice plus attempts/cost per successful output. Proposed budget: median attempts ≤1.1 per successful eligible call on normal fixtures, p95 first snapshot ≤110% of matched baseline. |
| T10 Financial accuracy review | Blind manual review by a domain reviewer and an engineer using the same fixture facts. Score numerical agreement, missing-data abstention, fundamental/risk reasoning, news interpretation, claim grounding, action alignment and schema separately. Compare cost and elapsed time only among candidates meeting quality gates. | 100% exact copied numbers, units and actions; derived numbers within specified rounding. Zero critical unsupported claims, contradictions or invented forecasts. Record pass count/denominator and review all disagreements. A small pilot cannot establish production percentiles or financial performance. |

Suggested offline order after approval: service/transport and factory tests, route/UI and concurrency tests, isolated integrity fixtures, then cost/latency report. Fail closed on egress, changed protected blobs, mismatched action provenance or a failing test. Do not update expected outcomes merely to make the candidate pass.

## Optional, separately budgeted live contract probe

Only after offline acceptance and written authorization for the exact model IDs, project, count and spend below. Use newly authored synthetic inputs with no customer data, `store:false`, Standard processing, no tools, background, streaming, cache writes, automatic retries or fallback. Pre-count all input including schema to **≤1,000 tokens** and configure **≤420 billed output tokens** each; if exceeded, cancel before sending. All prompts remain below the 6-family 1,024 visible-token caching threshold. Abort if account routing or prices would exceed cap. Eight requests total, one per fixture per model.

| Exact ID and profile | Purpose | Max calls | Max total input / output | Maximum token cost |
|---|---|---:|---:|---:|
| `gpt-6-luna`, low | Quick: normal, missing facts, conflict and exact numbers | 4 | 4,000 / 1,680 | $0.00124 |
| `gpt-6.1-terra`, low | Portfolio schema, locked conflict, unlocked supplied context and missing data | 4 | 4,000 / 1,680 | $0.01240 |
| **Total** | Standard USD, no other billable services | **8** | **8,000 / 3,360** | **$0.01364** |

Authorize a hard **$0.02** project allowance for this probe; no retries, no in-place model substitution and no additional paid experiments under that ceiling. Accept only if all valid fixtures return completed schema-conforming envelopes, remain within bounds, match expected safe behavior and contain no ungrounded numbers; record measured time, usage, reason/status and any model access denial. A refusal/incomplete/timeout is a failed probe or recorded abstention where explicitly expected, never a reason to expand the request budget. The probe verifies project availability and a small contract sample. It cannot authorize unlocked advice, certify Alpha Atlas or justify a paid rollout. A broader comparative study requires its own protocol, reference set and budget.
