## B · Configuration and reliability

Use the existing `AI_*` convention. Proposed configuration, to be reviewed rather than provisioned:

| Setting / precedence | Behavior |
|---|---|

| `AI_MODEL_QUICK_ASK` / `AI_MODEL_PORTFOLIO` → existing `AI_MODEL` → approved built-in profile | Explicit workload override wins. Validate the resolved ID against model card, lifecycle and project attestation; invalid explicit value stops the affected LLM work. Clearview uses Quick's profile unless separate behavior is later justified. |
| Per-workload effort, primary/retry output caps, timeout and attempt limit | Resolve once per app start. Represent immutable reviewed tuples in the existing `AIAdvisorService`; support independent Quick and Portfolio settings. Retain existing timeout/cooldown/TTL settings. Reject undefined effort, endpoint mismatch, negative/oversized caps and invalid combinations. |
| Per-workload fallback allowlist | Empty by default. Only a separately validated supported tuple with equivalent authority may be selected. For unlocked advice, explicit unavailability is the default until a quant-approved alternate exists. No automatic escalation to Sol/Astra. |

## D · Deployment, monitoring and rollback

December 4 is a target, contingent on ops and quant sign-off. Later deployment requires separate authorization. Prepare two **post-retirement-compatible** release/config pairs before any prod traffic: the new validated profile and an alternate build that understands approved supported profiles plus a verified no-inference state. Plainly reverting to this audited base reintroduces mini and minimal. Store only the release SHA and redacted profile version in the rollback record.

1. In an isolated preview with production credentials, DBs, market/AWS access and scheduled jobs disconnected, use synthetic fixtures and validate source branch, settings, and UI/API contracts. The current Blueprint startup at `render.yaml:12` may run migrations; review the preview target and its independent datastore before any deploy. No preview deployment is authorized by this audit.
2. Release to a small, explicitly selected preview/canary cohort if the approved release supports it. Capture first-paint time, successful advice latency and cost per accepted output. Proposed initial gate: zero protected-field drift, zero unsafe action contradictions, at least 99% completed valid responses among eligible healthy cases, no permanent model/parameter errors, and p95 first snapshot no more than 10% above a matched baseline. Small counts require raw denominators and owner review.
3. For a production smoke, prefer existing passive aggregates and provider-disabled synthetic health checks. A chargeable production smoke needs its own specific cap and approval beyond the isolated eight-request probe. Confirm live SHA, effective per-lane selection, fallback reason visible to user, usage and no work in market/cron paths. Ramp only with recorded release-owner approval; monitor daily Dec 5–10 and after Dec 11.
4. Stop ramp on any forbidden state change, invented recommendation, 400/404 model/config error, sustained 429/5xx, schema/latency threshold failure or cap overrun. Disable affected inference, keep deterministic functions serving and preserve logs. For Quick, restore validated Terra or Luna tuple only if it has passed the same narrative tests. For Portfolio keep the locked deterministic action; where action authority is absent display unavailable. Do not blindly flip today's global `AI_ENABLED=false` for unlocked rows because the current fallback creates a new recommendation.
5. Roll back code **and** environment as a reviewed pair. A suitably tested earlier compatible build may serve a supported ID with compatible effort; never switch to mini or a retired snapshot. Perform the same passive smoke and evidence checks after rollback. Record time, deploy SHA, effective tuple, affected lane, reason and recovery. Keep mandatory fixes separate from premium trials or a later configuration refactor.
